# Native provider attempt budgets

This candidate requires `state::provider_attempt_budget_v1` from the patched iii-engine SQLite StateModule. It has not been installed or proved against native execution. The old filesystem ledger is rejected and must not be provisioned. There is no environment-selected grant path, JSONL ledger, process lock, or in-process authority fallback.

The daemon receives its State SDK transport explicitly at startup. The provider-owning process runs selected work through `withProviderAttemptBudget({ operationId, windowId, ceiling, context? }, run)`. The three required fields and optional context are assertions against private engine configuration. They cannot create a grant. `getProviderAttemptBudgetReceipt(operationId)` is asynchronous and read-only; its result never authorizes a fetch.

`context` has exact keys `workflow`, `functionId`, `phase`, with optional `sourceId`, `jobId`, `unitId`, `continuationId`. Identity strings use `[A-Za-z0-9][A-Za-z0-9._:-]{0,127}`. A grant with context requires exactly the same present keys and values. A context-free grant accepts only a context-free assertion. The wrapper snapshots the binding and context before claim. Workflow callers may derive a stable continuation identity from their durable continuation text; the private grant must match that exact identity.

## Engine authority

Only the engine reads `provider-budget-grants.json` in the canonical directory of its configured SQLite database. No SDK request may supply this path or an authoritative ceiling. Missing, inaccessible, changed, malformed, oversized, symlink/reparse, or nonprivate configuration denies admission. The file and directory must be owned by a trusted identity. On Windows, native inspection of the opened handles requires a nonnull DACL and rejects every principal other than the engine process identity, SYSTEM, and Administrators. Unknown ACE layouts or unavailable inspection deny admission. Read handles deny write/delete sharing through commit. On Unix, engine/root ownership and no group/other mode bits are required. Unsupported platforms deny admission.

Version 1 configuration has only `version`, `window`, `allowedEndpoints`, and `operations`. `window` has `id`, canonical UTC millisecond `startsAt`/`expiresAt`, and `ceiling`. Each operation has `id`, `ceiling`, and optional `context`. Endpoints are canonical `METHOD scheme://host[:port]/path` strings with exact origin/path/method matching; credentials, query, and fragment are forbidden in configured endpoints. Bounds: 64 KiB configuration, 64 endpoints, 256 operations, 10,000 window attempts, 1,000 operation attempts, seven-day maximum window duration, 2,048-byte endpoint, 128-byte identities. These describe the file format; this source milestone does not create or modify a grant or ACL.

The first claim pins the normalized private window, endpoints, and every declared operation grant in native tables. The operator may append new grants under that same window after obtaining new durable workflow identities, including judge identities determined by generation results. The engine rereads the fixed private file on every action; no restart is needed. Append preserves every prior declaration by exact ID and keys/values/context/ceiling. JSON field, operation, and endpoint ordering is not authority; equivalent reordering is accepted. Removing, changing, or reusing an existing identity, altering endpoints/time bounds, or increasing the window ceiling fails closed. New declarations become durable atomically with the next successful claim/consume/finish mutation, even when those new grants are unclaimed. Status remains read-only and cannot pin a declaration. Operation identities are globally pinned even when not yet claimed; new windows must use new operation IDs. Closing or exhausting an operation never makes its identity reusable. Generic KV list/get/set/delete, reset, and pruning operate only on generic state rows and cannot enumerate or alter private native grants.

## Dispatch and recovery

Each claim, consume, and finish owns one explicit SQLite `Immediate` transaction. It runs on the StateModule connection without an outer/nested transaction and requires FULL synchronization for mutation. Both operation and window counts advance with the unique attempt insert in the same commit. Status reads only. A fresh positive consume ACK is returned only after commit. Duplicate/reconciled ACKs, status results, wrong identities, malformed counts, lost ACKs, timeouts, and cancellations authorize zero fetches.

Every raw retry and auxiliary fallback must await its own consume in the provider-owning process. A lost or uncertain ACK poisons that scope: no automatic reconsume, reconciliation dispatch, refund, or reopen follows. A consumed slot stays spent even when a process crashes before fetch. Interrupted claims remain `started` and are treated as unresolved; a later claim returns no fresh permission. `finish` closes as `completed` or `unknown`, never refunds. A failed finish remains unresolved until read-only reconciliation by the operator.

The native admission wait counts inside the caller's existing absolute fetch deadline. Abort and remaining time are checked again immediately before fetch. Scoped redirects are manual unless already `error`; each redirected provider request needs separately approved exact admission. Unscoped retry/redirect behavior remains supported.

The wrapper uses process-local async context. It does not cross `sdk.trigger`, WebSocket, subprocess, SDK-direct, detached worker, or other process boundaries. Callers must wrap the actual raw-fetch owner. All normal workflow selection and private-accounting matching remain separate integration gates. Never infer provider-wide coverage from this helper alone.

## Integration and rollback gates

One integrator must merge the native module, schema/bootstrap and storage dispatch hunks, Windows dependency and lock edge, capability advertisement/consumer/build hunks, startup injection, TypeScript replacement, and focused tests. Old sidecar tests must be retired with their source. Native fixtures must then run exclusively against isolated databases and Windows ACL fixtures before any live grant/service/provider action. The mocked tests establish only the JavaScript admission contract, not SQLite durability or Windows ACL correctness; see the handoff for exact raw receipts and the later elapsed-cap correction.

Before a downgrade, stop selected budgeted dispatch through its authorized runtime owner; retain the native private tables and all unknown/spent counts. Do not drop/recreate the database, restore a stale database, export/import generic KV as a budget migration, rewrite immutable grants, or enable the rejected sidecar. Any physical migration/restore must preserve these private tables conservatively. Revert source hunks only; native tables are additive and remain inert when unsupported. Native build, installation, actual grant provisioning, service restart, provider effects, and rollback execution require their later gates.
