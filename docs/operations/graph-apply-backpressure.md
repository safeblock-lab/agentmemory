# Graph apply queue backpressure

The SQLite state adapter keeps its 32-entry synchronous worker queue and 64 MiB request-byte admission budget. When that queue is full, a request first reserves its byte budget, then may wait asynchronously for a free queue slot for at most 60 seconds. At most 32 callers may wait this way. Each waiter holds its byte permit for the whole wait, so this does not create an unaccounted request buffer. Calls beyond either bound still fail before enqueue.

The 60-second pre-enqueue deadline is below the graph lease's 120-second TTL and the AgentMemory worker's 180-second invocation deadline. A request is retried only while `try_send` proves it was not enqueued. After enqueue, the caller awaits its single result; an unknown response is never replayed by the adapter. The native guard still validates at transaction execution, so expired or superseded leases remain fenced.

The external `STATE_TX_LIMIT_EXCEEDED` response remains compatible. Native logs distinguish adapter admission pressure (`sqlite_admission_bytes`), the bounded waiter cap (`sqlite_queue_waiter_limit`), queue wait timeout (`sqlite_queue_wait_timeout`), and the structural transport envelope (`sqlite_structural_envelope`). Successful queue waits are debug events (`sqlite_queue_backpressure`) and include only elapsed time and byte counts. Structural limits from SQL validation retain their existing error behavior.

Graph lease renewal uses one in-flight request per job. A timer tick during a renewal joins that promise instead of enqueueing another request. If the job has replaced its guard while an older renewal was pending, that older failure is logged against its stale identity and does not poison the current guard. After successful work, an old-lease `STATE_TX_FENCED` or `STATE_TX_GENERATION_STALE` is treated as expected only when the control record proves the generation advanced and the failed renewal used this job's exact acquired owner, generation and fence. Finalization stops the timer, waits for any outstanding renewal, attempts lease release, preserves the primary operation error, and propagates other renewal or release errors. A current-guard renewal error is stored on the job's lease guard and prevents later writes under that guard.
