# AgentMemory growth recovery activation (2026-10-05)

These local scripts stage the cutover from the contained 0.9.81 process to the verified 0.9.82 package and cleaned SQLite image. They have not been executed by their author. The authoritative release checks remain in [AgentMemory 0.9.82 release acceptance](agentmemory-0.9.82-release.md).

## Gates

`Invoke-GrowthActivation.ps1` refuses to run until the isolated cleanup receipt's last phase is `verified`, `package-candidate.json` records `acceptance.fullSuitePass=true`, and a Main-reviewed marker is supplied with its exact SHA-256. Both scheduled tasks must be disabled; AgentMemory may still show `Running` while its old writer is suspended. The marker expires after 30 minutes and binds all four old processes to PID, parent PID, creation time, executable path and command-line hash, with the engine executable under the AgentMemory service home and its launcher tied to the scheduled task action. It requires every iii writer thread to be suspended. Because the suspended writer can lock the old SQLite files, the marker records DB/WAL/SHM presence, size and UTC write time twice without reading their contents. It hashes the cleaned file set. Activation rechecks old metadata before and after stopping the exact old tree, then requires complete hashes and a verified private backup of every old file before removing anything on C:. Tasks must be stopped after the old tree exits. It also binds task actions, package and receipt hashes, and service-log offset. Run the read-only `Get-GrowthActivationMarker.ps1` only after those gates pass, review the resulting private JSON, set `mainReviewed` to `true`, and pass the final file SHA-256 as `-ReviewedMarkerSha256`. Never publish the marker or the private API header file.

The API header file is a private JSON object containing an `Authorization` header for the existing local API. Put it under `D:\agentmemory\artifacts\private\`; keep its contents out of logs and Git. Run PowerShell 7 elevated. The marker also binds the current `C:\Program Files\nodejs` junction target. The script copies and verifies the installed package before stopping the old process chain, then backs up the stopped SQLite DB, WAL and SHM to the private D: rollback directory before removing the C: originals. It does not touch configuration, snapshots, other SQLite files, graph indexes, local model files or task definitions. It installs the exact local tarball with npm offline and lifecycle scripts disabled, starts `AgentMemory` once, and leaves the watchdog disabled for subsequent health acceptance.

Example invocation after Main review:

```powershell
$script = 'D:\agentmemory\.native-pagination-build\growth-activation-20261005\Invoke-GrowthActivation.ps1'
$marker = 'D:\agentmemory\artifacts\private\growth-activation-reviewed.json'
$hash = (Get-FileHash -LiteralPath $marker -Algorithm SHA256).Hash
& $script -ReviewedMarker $marker -ReviewedMarkerSha256 $hash -HealthHeaderFile 'D:\agentmemory\artifacts\private\local-api-headers.json'
```

Any failed gate stops the script. A failure after old-file removal but before the first start attempt restores the exact old DB/WAL/SHM set from D: while both tasks remain disabled, and verifies every restored hash. The task enable and start calls share a failure handler: enable failure disables the task and permits pre-start recovery; immediately before the start call, the script switches to preserving new data. Once startup has been attempted, data is never replaced automatically: new writes may already exist. A failed post-start check disables the AgentMemory task to prevent a relaunch; inspect the running process, new DB and log before recovery. Running MCP clients are not treated as daemon writers. The separate `Restore-GrowthPackage.ps1` restores only the 0.9.81 application package after a separately reviewed stop of the new process tree; it requires disabled tasks, free managed ports and a fresh Main-reviewed marker with purpose `agentmemory-package-only-rollback`, the backup manifest SHA-256, reviewed `nodejsTarget` and a future `expiresUtc`. It quarantines an existing package even if it is corrupt; a failed restore leaves that quarantine intact. It does not restore data or start the service. Main must decide whether restarting 0.9.81 is safe, since it lacks the graph-growth correction.

The initial script's health check covers API version/status, viewer, port ownership and the new log suffix. Main must still run the bounded live consolidation/snapshot acceptance, restore task enablement according to the saved XML, verify watchdog behavior, and monitor database growth after startup.
