# Local agent usage

The savings report combines the local person's available Codex and Claude Code response usage over one exact seven-day UTC interval. One installed client is normal. Colleagues' profiles and remote machines are not aggregated. `agentUsage.clients` retains each client's coverage (`available`, `empty`, `unavailable`, `partial`), model counts and timestamps; the combined ratio is total cache-read tokens divided by total input tokens, never an average of percentages.

Codex reads individual `token_usage_record` responses belonging to the rollout's own thread, deduplicated by response ID. Cumulative events and inherited parent responses are excluded. Its input token count already includes cache reads/writes. Claude reads assistant `message.usage` records from `CLAUDE_CONFIG_DIR/projects` or `~/.claude/projects`, including subagent directories, deduplicating message IDs across streaming snapshots and fork copies. Input categories must remain identical for a message; contradictory duplicates are rejected and mark coverage partial. Only cumulative output uses the maximum across valid snapshots. Claude input is `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`, as specified by [Anthropic's prompt caching documentation](https://platform.claude.com/docs/en/build-with-claude/prompt-caching). Output includes the reported output count, not a second reasoning-token addition. Unsafe combined totals become null and partial, suppressing the cache ratio and valuation rather than publishing imprecise numbers.

`agentUsage.modelUsage` contains one row per client and recorded model. Codex responses use their own `payload.model` or the model of an earlier `turn_context` with the exact same turn ID in the same file and owning session. The reader does not use configured defaults, the most recent unrelated turn, or a later context to fill earlier requests. Session metadata clears the correlation map, including malformed boundaries. The map shares the 20,000-record bound. Unknown contexts remain unknown, including when a previous turn had a known model. Claude uses the assistant message's recorded model. Deduplicated request shares, input token shares, output token shares, and total token shares use **all sampled records, including unknown/unpriced models**. Shares are fractions from zero to one; total tokens mean input plus output, without adding reasoning a second time. Combined rows use combined denominators; client rows use client denominators. Unsafe or empty denominators produce null.

`modelUsage[].pricing` and combined `agentUsage.pricing` expose separate `costsUsd.input`, `cacheRead`, `cacheWrite`, `output`, and `total`. Input cost covers only input tokens that are neither cache reads nor cache writes. `weightedRatesUsdPerMillion` gives the effective category rate across that model's recorded requests, including supported tier/context modifiers; it is null for an unused or incompletely priced category. `pricedSubtotalUsd` sums only known category costs and is explicitly distinct from a total. Unknown models, moving aliases, unsupported platforms/tiers/geographies and missing cache-write tariffs remain unpriced, with bounded reason codes and `unpricedRequests`. A missing category propagates null to the category aggregate and total; known category subtotals survive. Empty usage has null monetary totals.

The tariff catalog was checked on **2026-10-09** against [OpenAI API pricing](https://developers.openai.com/api/docs/pricing), the [GPT-6.1 Sol model documentation](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra), [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna), [GPT-5.6 Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol), and [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing). [GPT-6 Sol](https://developers.openai.com/api/docs/models/gpt-6-sol) retains its own documented rate rather than receiving GPT-6.1 prices. The catalog supports the explicitly listed GPT families and Claude models; unavailable tariffs are never guessed. Exact dated snapshots retain their named family's current scenario tariff; moving `latest` aliases are unpriced. Rates are USD per million tokens. Reasoning effort is not a tariff selection or a fabricated surcharge.

These are **current direct API equivalent scenarios**, not historical charges, subscription refunds, provider bills, negotiated discounts, tax or tool costs. Recorded supported service tiers are honored. Missing tier/platform/geography uses an explicitly labelled standard/direct/global scenario and increments `scenarioRequests`; an explicit unsupported value remains unpriced. GPT-6 requests above 272,000 total input tokens apply their documented long-context rates for the entire request; GPT-6 Batch/Flex, Fast/Priority and supported Ultrafast modifiers are applied per record. Unknown OpenAI residency endpoints remain unpriced. Claude supports recorded batch, supported fast mode and US inference geography; current newer Claude context rules apply, while unestablished legacy long-context tariffs stay unpriced. Claude write pricing uses the reported `cache_creation.ephemeral_5m_input_tokens` and `ephemeral_1h_input_tokens` split. If either split is missing or inconsistent, write cost and total are null rather than assuming the five-minute price. Conflicting duplicate tariff metadata marks the sample partial and preserves the first coherent response.

Savings no longer exposes a fixed Sol/medium baseline or a fixed-model processing range. Selection's only monetary scenario uses the measured sample's cache-weighted input price and remains null if input pricing is incomplete. Profile coverage can still be partial even when every sampled token has a scenario price. This scenario is hypothetical exposure at the observed model mix, not proven avoided spending. Legacy processing metrics omit model/tariff metadata and therefore expose counts and tokens without monetary valuation. The processing module retains its legacy internal scenario helper for compatibility; that range is removed from the savings response. Cache discounts belong to provider cache behavior, not proven agentmemory savings.

Each collector cooperatively stops at 2.5 seconds, 4,096 discovered entries, 512 directories, 100 files, 64 MiB read or 20,000 unique responses. Directory iteration uses bounded handles, skips symlinks, caps depth at 16 and paths at 4,096 characters, and never builds a whole-profile file list. Retained IDs and model names are capped at 256 characters. Codex default discovery addresses only eight UTC date directories. Input is read in 64 KiB chunks; lines above 256 KiB are discarded until newline without accumulating their contents. Budget exhaustion, malformed usage and read errors mark coverage partial. Operating-system file calls are awaited; the deadline is cooperative rather than a guaranteed hard I/O timeout. A five-minute, process-local single-flight cache prevents concurrent report scans. No transcript text, local paths, credentials or error payloads are returned.

The scan is a bounded sample, not a complete accounting export: a large active profile may be partial. Missing usage is never fabricated. Agent-isolated server mode retains the existing prohibition on attributing unlabelled local profile records to an agent.
