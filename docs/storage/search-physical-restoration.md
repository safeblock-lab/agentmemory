# Bounded search recovery and physical maintenance admission

The internal function `mem::indexed-source-recover` invokes the existing incremental recovery method for the active local384-dimensional embedding identity. It retains its60-second,16-page and128-source bounds, exact source versions and fail-closed embeddingReuse restriction. Local model loading uses cached files only. No MCP or REST endpoint, corpus rebuild or external provider call is introduced. A missing cache or incompatible source remains an error.

Physical maintenance admission is independent of legacy observation-identity repair and destructive retention activation. It requires accepted format4, exact completed root/text/search recipes, the measured combined saving and an acknowledged final checkpoint. It records a DB+WAL baseline with physical-only coverage, preserving the existing observationIndex.complete value, cleanupActivatedAt and corpus diagnostics.

An admitted tick measures physical metadata only and returns before legacy census/index/retention callers. Existing durable cursors, receipts, graph fences and1GB growth gates remain authoritative. The stopped zero-yield TTL and global GC executions are not resumed on initial activation; no fresh global collection or reclaim begins below1GB. Pending operations still reconcile before fresh work. Retention cleanup remains separately gated.

Main reloads only the owned application after an isolated-console graceful exit, preserving the compatible existing engine. Physical-only admission precedes launch with background recovery paused and maintenance while paused enabled; the operator then invokes bounded local dirty recovery through SDK. Source/application emission is grouped once; no native re-emission is needed.
